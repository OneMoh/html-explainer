# 封面指南（cover-guide）

成片出来后**必须出封面**。这不是可选步骤——封面决定点击率，而成片
只决定完播率；一张被切掉半个钩子的封面会让整片白做。

## 一张还是几张？

**默认出两张（16:9 + 3:4），竖版投放再加第三张 9:16。**

| 场景 | 出哪几张 |
|---|---|
| 横版视频投抖音/视频号（常规） | `169` + `34` ✅ 默认 |
| 竖版视频（1080×1920 成片）、全屏竖版信息流、小红书图文/视频、朋友圈 | 再加 `916` |
| 用户明确点名某个画幅 | 按用户说的出，可只出那一张 |

## 一、为什么是「独立排版」而不是「一张裁几版」

成片画布 1920×1080。平台上主页栅格按 **3:4** 裁，竖版成片按 **9:16** 展示：

| 从 16:9 裁过去 | 结果 |
|---|---|
| `h=1080` → `w=810`（3:4） | 丢掉 **1110px = 57.8%** 的画面宽度 |
| `w=1080` 等比 → 只剩 608px 高（9:16） | 丢掉 **43.7%** 的画面高度，上下被砍 |
| 钩子如果横跨全宽（大字常常如此） | **必被切**，只留中间一截 |

所以「兼容 3:4 / 9:16 的版本」定义是：**同一套视觉基因（配色/幕底/主视觉/钩子文案），
为那个画幅重新排一次版**。三份是姊妹图，不是母子图。

```
frames/cover_169.html   1920×1080  →  out/cover_169.png    抖音主封面（信息流/播放页）
frames/cover_34.html    1440×1080  →  out/cover_34.png     主页栅格兼容（防切字）
frames/cover_916.html   1080×1920  →  out/cover_916.png    竖版全屏 / 小红书 / 视频号竖版
```

## 二、各画幅的排版纪律

### A. 1920×1080（抖音主封面）

| 项 | 规格 |
|---|---|
| 钩子字号 | **≥96px**（建议 110–130px），全画面最大最亮 |
| 主体视觉 | 偏左或偏右，**不要居中**——信息流两侧会被 UI 压住 |
| 安全边距 | 四边 ≥96px；关键元素集中在**中间 80% 区域** |
| 悖论视觉 | 放右侧时数字可到 140–160px |
| 底部 | 可放角标/栏目名（16:9 版底部不会被裁成方图），但仍留 ≥96px |

### B. 1440×1080（兼容 3:4）

这是**真正的 3:4**（1440:1080 = 4:3，视觉上等价 3:4 的宽高比），不是裁出来的。

| 项 | 规格 |
|---|---|
| 钩子字号 | **120–150px** —— 画幅窄了，字必须更大才够冲击 |
| 布局 | **上中下三段式**：视觉在上 55%、钩子在下 45%，或反之 |
| 左右边距 | ≥110px（窄画幅比例上边距要更大） |
| 悖论视觉 | 改成**竖排堆叠**（16:9 是左右并置）——这是"重排"的核心动作 |
| 禁止 | 横跨全宽的细长元素（会被裁成断线）；贴边文字 |

### C. 1080×1920（竖版 9:16）

竖版不是「把 3:4 拉长」——画幅一变高，**左右并置必须改成上下堆叠**，
否则两栏都会窄到放不下字。

| 项 | 规格 |
|---|---|
| 钩子字号 | **130–170px** —— 竖版在信息流里按宽度等比缩放，字号不放大就完全看不清 |
| 布局 | **上中下三段式**：角标 0–10%、视觉 10–45%、钩子 50–88% |
| 左右边距 | ≥90px（画幅窄，绝对边距可以小一点，但**不能贴边**） |
| 上边距 | **≥180px** —— 竖版全屏顶部有平台信息层（账号/时长），压上去等于自杀 |
| 下边距 | ≥160px —— 底部有标题栏与互动按钮，会被压住 |
| 悖论视觉 | **只能竖排堆叠**，数字缩到 96–130px（横排并置在 1080 宽里必然挤） |
| 每行字数 | 钩子 **≤6 字 / 行**（1080 宽、150px 字号，扣掉左右边距只剩 ~7 字位） |
| 禁止 | 横跨全宽的细长元素、左右两栏、贴边文字、把 16:9 版直接旋转/拉伸 |

**9:16 的构图重心偏上**：观众拇指在下方、视线从上方进入，钩子放在 50–88% 高度区间
比放在正中间更稳（正中间那一带最容易被底部标题栏挤掉）。

## 三、重排对照（同一份内容，三种摆法）

| 元素 | 16:9 版 | 3:4 版 | 9:16 版 |
|---|---|---|---|
| 悖论视觉 | 右侧，左右并置 | 上方，竖排堆叠 | 上段（10–45%），竖排堆叠，且**拆成上下两行** |
| 钩子 | 左下，两行 | 下方，两行 | 中下段（50–88%），**三行** |
| 角标 | 左上 | 左上 | 顶部居中或左上（留 ≥180px 上边距） |
| 主视觉字号 | 数字 118px | 数字 112px | 数字 96–130px（画幅最窄，缩一档） |
| 钩子字号 | 130px | 130px | **150px**（放大，抢占视觉） |
| 钩子每行 | ≤8 字 | ≤8 字 | **≤6 字** |
| 钩子容器宽 | 1060px | 1220px | 900px |
| 分裂线 | 右栏内横线 | 横贯（留边距） | 横贯（留边距）；**不要用竖线** |

## 四、封面三要素（缺一返工）

### A. 大字钩子

一句话让人停下。**必须含反差/悬念**，验证方法：把这句单独发出去，会不会有人点？

| 好钩子 | 坏钩子 |
|---|---|
| 同一件事，为什么两拨人的感受完全相反 | 关于 X 的几个事实 |
| 涨了 38%，他们却在退出 | XX 行业分析 |
| 这条规则，让所有人都在做同一件蠢事 | 今天聊聊 XX |

字号 ≥96px（3:4 版 ≥120px、9:16 版 ≥130px），关键词用 `<em>` + accent 色 + 柔光。

### B. 核心悖论视觉

画面主体本身要**在讲一个矛盾**——不是装饰图形。可选形态：

- **双数对照**：一升一降的两个数字（见模板 `.paradox`），最直接
- **分裂线**：一道斜切/裂缝把画面分成两半，两侧不同色
- **撞色块**：accent 与 signal 两个色块相互挤压/重叠
- **一明一暗**：主体一半在光里一半在暗处

**禁止**：中性几何装饰、无意义的曲线、跟内容无关的图标。

### C. 信息余量

平台四边会再裁一点（各平台 2–5% 不等），竖版还要额外让开平台的顶部信息层与底部标题栏。

- 钩子距边 ≥96px（3:4 版 ≥110px、9:16 版左右 ≥90px）
- **9:16 版上下边距特殊**：上 ≥180px、下 ≥160px —— 顶/底是平台 UI 层，不是可裁区
- 不要有贴边文字、贴边细线
- 16:9 版的关键信息集中在中间 80%

## 五、尺寸与倍率

| 规格 | CSS 画布 | 实际输出像素 |
|---|---|---|
| `169` | 1920×1080 | **3840×2160**（`--scale 2` 默认，2 倍清晰度） |
| `34` | 1440×1080 | **2880×2160** |
| `916` | 1080×1920 | **2160×3840** |

2 倍是为了应付平台压缩和高分屏；字节数约 1–3MB，上传无压力。
要 1 倍原尺寸用 `--scale 1`。

## 六、用法

```bash
# ① 复制模板，做几张就复制几份（改尺寸 + 重排版式 + 填真实钩子）
cp <skill>/assets/cover-template.html <项目>/frames/cover_169.html
cp <skill>/assets/cover-template.html <项目>/frames/cover_34.html
cp <skill>/assets/cover-template.html <项目>/frames/cover_916.html   # 竖版投放才要

# ② 渲染（默认 seek 到时间轴末尾取完整态；缺哪张就跳哪张）
node <skill>/scripts/cover_build.mjs <项目>

# 常用变体
node <skill>/scripts/cover_build.mjs . --at 0.8      # 取入场动画中间态（更有张力）
node <skill>/scripts/cover_build.mjs . --only 169    # 只出 16:9
node <skill>/scripts/cover_build.mjs . --only 916    # 只出 9:16
node <skill>/scripts/cover_build.mjs . --jpg         # JPEG（体积小，平台都收）
node <skill>/scripts/cover_build.mjs . --scale 1     # 不要 2 倍
```

产出：`out/cover_169.png`、`out/cover_34.png`、`out/cover_916.png`（视存在情况）、
`out/cover_report.md`

## 七、上传策略

| 场景 | 用哪张 |
|---|---|
| 抖音信息流 / 播放页主封面 | `cover_169.png`（选「横版封面」） |
| 抖音个人主页栅格 | `cover_34.png`（选「竖版封面」） |
| 平台只允许一张 | **用 `cover_34.png`** —— 多数主页栅格按 3:4 裁，16:9 会被切两侧 |
| 小红书 / 视频号 / 竖版全屏信息流 | `cover_916.png`（画幅本身就按 9:16 展示） |
| 用户点名 9:16 | 只出 `cover_916.png` 也可以 |

**封面文字必须与视频首帧钩子一致**（或至少同义）——观众点进来看到的是同一个承诺，
不一致会立刻跳出。

## 八、自检清单（上传前逐条过）

> **先跑 `check_cover.mjs`，再逐条肉眼过。**
> ```bash
> node <skill>/scripts/check_cover.mjs .            # 量全部存在的封面
> node <skill>/scripts/check_cover.mjs . --only 916 # 只量一张
> node <skill>/scripts/check_cover.mjs . --shot     # 顺手出 1x 预览图
> ```
> 它一次判完：四边边距 / 钩子字号 / **钩子是否仍是最大文字**（纯数字另算）/ 行宽 /
> 孤行 / 9:16 禁左右两栏 / 越界。退出码 0 才算封面过。
>
> **两个必须知道的实现细节**（否则会量出"假错误"）：
> 1. **必须量终态。** 页内若有 GSAP 时间轴，脚本会先 `tl.pause(tl.duration(), false)`
>    再量；否则量到的是入场起始值，边距/行数/字号全错，而且**看起来像真错误**
>    （lessons #30 / #84）。
> 2. **钩子识别与"钩子是否最大"是两条独立判据。** 脚本把"自身文本 ≥6 字位且不是纯数字串"
>    的元素视为句子级候选，在其中取字号最大者为钩子；这样「6.02」这类悖论数字不会被
>    误判成钩子。数字比钩子大只给提醒（上限 钩子×1.35），**文字比钩子大才是 FAIL**。
