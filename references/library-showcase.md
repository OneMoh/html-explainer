# 库全量演示（Library Showcase）—— 把 40+ 动作一次演完还不像流水账

> **一句话**：全量罗列天生是流水账；要救它，靠的不是「剪快点」，而是**三个固定**。

**什么时候读**：用户要求「展示全部动效 / 全部模板」，
或全片有一节的任务是「把库的规模讲清楚」而不是「把某一个讲深」。

配套读：`references/showcase-mode.md`（六条设计律）、`references/motion-library.md`（动作清单）、
`references/style-catalog.md`（23 个模板风格）。

---

## 1. 核心矛盾

| 想要 | 代价 |
|---|---|
| 全量（40+ 条都要出现） | 每条只能分到 0.6–1.0 s → 观众来不及看 |
| 看得清（每条都要看懂） | 每条要 2–4 s → 40 条 = 100 s+，全片被撑爆 |

**出路不是二选一，是「降维」**：不给每条独立的构图，让**所有条共用同一个舞台**。
观众只学一次阅读规则，之后每一拍都是在同一张脸上换表情 —— 这是从「40 个片子」变成「1 个片子的 40 拍」。

---

## 2. 三条编排法（三个固定）

### 固定 ① 统一舞台（Uniform Stage）

- 舞台上**位置固定**：主角槽位、标签槽位、刻度槽位全片不动。
- 每条演示**只换主角**，不换构图。
- 主角用同一个形状起步（一个方块 / 一枚圆盘），靠动作把它变成不同形态 —— 这样「动作」才是唯一的变量。

### 固定 ② 节拍网格（Beat Grid）

- 每条占**整数拍**，例如 2 拍 = 1.0 s（按 120 BPM 的 1/4 拍）。全片同一拍长，不忽快忽慢。
- 组内第 k 条的起拍 = `组起点 + k × 拍长`，**可被公式预测** —— 观众会在第 3 条时学会节奏。
- 节拍网格是全片的节奏骨架：每条起拍一次动作、组末加重收束，**起拍间隔可被公式预测** —— 观众会在第 3 条时学会节奏。

### 固定 ③ 标签常驻（Persistent Label）

- 舞台角落常驻一个标签位，显示**当前动作名 + 关键参数**（如 `springIn  ω=18`）。
- 标签**在每条结束时翻页**（配一次轻量的位置切换动作）—— 观众的眼睛可以「先看动作、再看名字」。
- 标签用等宽字体，参数对齐 —— 这一格字的整齐本身就是「工程感」。

> 三条合起来的判据：**遮住画面只看标签，能读出一份完整清单；遮住标签只看画面，能看出一套统一的动作语言。**

## 3. 分组：按叙事阶段切，不按字母序

`assets/motion.js` 的 5 组正好是 5 个叙事阶段，直接用作章节：

| 组 | 动作数 | 章节主张 |
|---|---|---|
| `enter` | 8 | 「什么东西怎么到场」 |
| `carry` | 8 | 「下一镜怎么从这个镜里长出来」 |
| `contact` | 6 + `sim.*` | 「一件事怎么引发另一件」 |
| `camera` | 8 | 「镜头怎么动」 |
| `ambience` | 6 | 「环境和光怎么呼吸」 |

**组间必须 carry**（见 `showcase-mode.md` 第 3 律）：上一组最后一个动作的元素，
用 `diveInto` / `irisOpen` 变成下一组的舞台。这样 5 组不是 5 段，是一条链。

## 4. 时长预算（先算再做）

```
组时长 = 组标题过场(1.0–1.5 s) + 组内条数 × 拍长
全片库节 = Σ 各组时长 + 组间 carry(0.4 s) × (组数-1)
```

以 8 条 / 拍长 1.0 s 为例：`1.2 + 8×1.0 = 9.2 s` 一组，5 组 + 4 次 carry ≈ **47.6 s**。

> 这就是「120 s 片子里，库演示能占多久」的答案：**约 40 s（1/3）**。
> 超过 1/2 就会把叙事挤没；少于 1/4 就讲不清「规模」。

**模板风格谱**是另一种库演示（23 个模板 / 8 个类别），拍长可短到 0.7–0.8 s：
按**类别**排成一条横轴（大胆信号卡 → 瑞士网格 → 胶片漏光 → …），
每换一格点亮一个模板名 —— 让「23 个模板」在同一张脸上依次换装。

---

## 5. 每条的「演示位」格式

```json
{ "i": 3, "name": "landHit", "arg": "ω=22 decay=0.18", "t0": 12.4, "dur": 1.0 }
```

- `name` / `arg` 直接喂给标签槽；
- `t0` 落在节拍网格上 —— 「动作与节拍同源」就落在这一格上。

---

## 6. QC 判据（渲完抽帧自查）

| 判据 | 怎么看 |
|---|---|
| **每条可单独辨认** | 抽 3 条的首帧，遮住标签也能说出是「落地」还是「甩镜」 |
| **标签与动作同步** | 标签翻页时刻 = 动作起拍时刻，误差 < 1 帧 |
| **节拍可预测** | 抽任意连续 3 条，起拍间隔相等 |
| **不糊** | 快动作（`whipPan` / `arcHop`）没有重影成串 → 快门已开 |
| **有起伏** | 组末是全组动势最重的一拍，中间各拍明显更轻（`motion_intensity` 有高低） |

## 7. 反模式（踩过的坑）

| 反模式 | 为什么糟 | 改法 |
|---|---|---|
| 每条换一个版面 | 观众每拍都要重新学阅读规则 → 累 | 统一舞台 |
| 用淡入淡出连接每条 | 读成 PPT（`motion-library.md` 明令：慢动作别用纯 opacity） | 用 `riseWord` / `morphBox` 有实感的进出 |
| 40 条均匀 1 s | 无重音、无呼吸 | 组末加长 + 加重 |
| 每条都上满强度 | 无重音、无呼吸，观众很快疲劳 | 组末加重，组内多数条目收着做 |
| 标签和动作同帧出现 | 眼睛被迫二选一 | 标签**延迟 6–10 帧**翻页 |
